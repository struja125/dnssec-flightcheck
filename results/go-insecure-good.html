Corrected plan (YAML)
name: Turning DNSSEC off, DS first
description: 'The DS is removed first; the zone keeps its keys and signatures until
  the old DS has expired from every cache (registry delay + DS TTL).

  '
zone: bank.test.
start: 2026-11-02 12:00:00+00:00
delays:
  propagation: 5m
  registry: 1h
margin: 1h
keys:
  KSK1:
    role: ksk
    algorithm: ECDSAP256SHA256
  ZSK1:
    role: zsk
    algorithm: ECDSAP256SHA256
initial:
  ds:
    keys:
    - KSK1
    ttl: 1d
  dnskey:
    keys:
    - KSK1
    - ZSK1
    signed_by:
    - KSK1
    ttl: 1h
  data:
    www:
      signed_by:
      - ZSK1
      ttl: 1h
steps:
- name: Remove the DS
  at: 0s
  ds:
    keys: []
    ttl: 1h
- name: Unsign the zone
  at: 1d3h
  dnskey:
    keys: []
    signed_by: []
  data:
    www:
      signed_by: []

Notes

  • info · plan: DS changes take effect 1h after submission (registry delay)
Worst-case analysis: a version can stay in a resolver's cache for a full TTL after the last authoritative server stopped serving it. Conservative model = RFC 7583 assumptions (any cached versions may be combined, as for validators behind caches); fetch model = a validating resolver that validates on fetch and trusts its cache.
