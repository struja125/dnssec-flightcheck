ZSK rollover (pre-publish), new ZSK used immediately

Zone bank.test. · conservative model · propagation 5m · registry delay 0s · max cache TTL 7d · start 2026-11-02 12:00 UTC
SAFEno bogus answers at any moment

The new ZSK is published and used for signing in the same step, and the old ZSK is removed two hours later. Resolvers that still cache the old DNSKEY RRset cannot validate data signed by the new ZSK, and the mail record (TTL 1 day) keeps old signatures in caches long after the old ZSK is gone.

Worst-case analysis: a version can stay in a resolver's cache for a full TTL after the last authoritative server stopped serving it. Conservative model = RFC 7583 assumptions (any cached versions may be combined, as for validators behind caches); fetch model = a validating resolver that validates on fetch and trusts its cache.
